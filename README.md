Ответы на контрольные вопросы
1. IL - это промежуточный код, в который компилируется C#. Нужен, чтобы программа не зависела от конкретного процессора: JIT уже при запуске превращает IL в машинный код под нужную архитектуру.
2. Потому что внутри сборки лежат IL и метаданные (имена классов, методов). Их достаточно, чтобы ILSpy восстановил код, похожий на исходный. 
3. В Debug куча лишнего: nop, .locals init. В Release компилятор это выкидывает - IL короче. 
4. Компилятор и JIT применяют больше оптимизаций: убирают промежуточные переменные, отладочные вставки и лишние переходы. Но Release не всегда быстрее - зависит от кода, .NET и процессора, поэтому и измеряем.
5. Строки хранятся в сборке открытым текстом (UTF-16), их видно в HEX-редакторе. Поэтому пароли и ключи в коде хранить нельзя - их легко достанут.
